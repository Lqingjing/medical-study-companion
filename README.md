# 医学伴学教辅 · Medical Study Companion

> 把网课讲义、分层题库、主动回忆与按章记录放进同一个本机页面的学习工具。
>
> **本仓库是 V0.1 的代码与设计公开展示版，不是可直接运行的软件。** 医学讲义、题库、章节内容源与真实学习记录均不在公开范围内。

---

## 一、它解决什么问题

医学生看网课时常见的断点不是"没资料"，而是：

| 断点 | 具体表现 |
|---|---|
| 讲义与视频分离 | 老师讲到某页，回头找不到原句；笔记和讲义对不上 |
| 看完就忘 | 视频看懂了，关掉页面后无法用自己的话重建机制 |
| 题与讲义脱节 | 做错题后只知道答案，不知道对应讲义哪一页、哪一句 |
| 记录散落 | 作答、理由、追问留在聊天或纸上，换设备或隔天就断 |

V0.1 提供的是应对这些断点的**基础能力**：在一个本机页面里读原讲义、按层做题、看题后反馈并跳回原页、把作答与追问按章存下来。把这些能力自动串成"继续学习 → 原页 → 关联题 → 答疑 → 恢复"的任务流，是 V0.2 正在做的事，**不属于 V0.1**。

## 二、V0.1 已验证的能力

V0.1 以两个章节为样本完成：**支气管哮喘** 与 **肺血栓栓塞症（PTE）**。以下能力均在本地隔离环境验收过：

| 能力 | 实际行为 | 说明 |
|---|---|---|
| 原讲义阅读 | 内嵌 PDF.js 阅读原始讲义页，按小节定位 | 讲义本身不随仓库公开 |
| 导图与来源页 | 小节关联导图、来源页与书页码换算 | 页码偏移在内容源中配置 |
| 分层题库 | 同一章按"课后 / 执医 / 考研"三层组织，哮喘 167 题、PTE 84 题 | 题目内容不公开 |
| 题后反馈 | 提交后给出答案、解析、题眼，并标注对应小节与讲义页 | 反馈可跳回原讲义页 |
| 作答记录 | 记录选择、理由、次数；按章保存；刷新与重开可恢复 | 保存在本机 JSON，不入仓库 |
| 历史作答兼容 | PTE 旧题号（`tt-pte-1`）在当前题号（`tt-pte-01`）下仍能读回旧理由 | 只读映射，不改写旧记录 |
| 原文选区答疑 | 选中讲义文字或题目卡，连同小节、页码、题号一起提问 | 依赖本机已登录的模型客户端 |
| 勾画与批注 | 在讲义页上勾画，状态本地保存 | — |
| 入口与构建 | 双击入口启动本机服务；一条命令完成"编译 + 门禁" | 门禁脚本随仓库公开 |
| 质量门禁 | `verify_unit.py` 检查 HTTP、PDF 流、章节路由、入口文件；`test_server.py` 覆盖服务端行为 | 见 `docs/验收摘要.md` |

**这些能力是分别实现并分别验收的，不代表 V0.1 已经具备跨小节的自动任务编排。**

## 三、V0.1 与 V0.2 的边界

| 能力 | V0.1 | V0.2（本地工作区已完成第一段，未发布） |
|---|---|---|
| 按小节读原讲义、翻页、选字、勾画 | 有 | 沿用 |
| 分层题库、题后反馈、跳回原页 | 有 | 沿用 |
| 按章保存作答与追问 | 有 | 沿用 |
| 进入章节时的定位 | 默认从首节开始，可手动切换 | 按"显式链接 → 已存小节 → 首节"自动定位 |
| 讲义页与本节关联题 | 需自行进入练习小节 | 讲义页直接提供本节关联题入口 |
| 从题卡返回原讲义 | 返回后需重新定位 | 保留阅读器与滚动位置 |
| 提交后的计数刷新 | 需刷新或重进练习 | 原练习页同步重绘 |
| 跨小节任务流编排 | **没有** | 部分（第一段），尚未验收发布 |

V0.2 只改了前端 `app.js`，沿用 V0.1 的后端接口与数据结构；它尚未发布，也未被描述为完成版。

## 四、架构

```
内容源 (content/*.json)        本地讲义 PDF / 题库原始文件
        │                              │
        └──────────┬───────────────────┘
                   ▼
        compile_units.py   ──►  {unit}.json（章节数据：小节/题目/反馈映射）
                   │
                   ▼
        server.py（本机 HTTP 服务）
          ├── /api/units /api/unit /api/state   章节与小节状态
          ├── /api/attempt /api/annotation      作答与勾画
          ├── /api/position /api/recall         阅读位置与主动回忆
          ├── /api/ask                          追问（经本机模型客户端）
          └── PDF 流                             原讲义按页返回
                   │
                   ▼
        app.js + original-reader.js（浏览器端）
          ├── 章节/小节导航、分层题库、题卡反馈
          └── PDF.js 阅读器：翻页、选字、勾画、跳回原页
```

- 后端：Python 标准库 `http.server`，无第三方 Web 框架。
- 前端：原生 JavaScript，无构建步骤、无前端框架。
- 数据：每章一个 `session.json`（本机），题目与讲义不写入仓库。
- 门禁：`build_unit.py` 编译后自动跑 `verify_unit.py`；`test_server.py` 用临时会话隔离测试。

更细的模块职责见 [`ARCHITECTURE.md`](ARCHITECTURE.md)。

## 五、目录

```
app/tutor/
├── server.py            本机 HTTP 服务：章节、作答、位置、追问、PDF 流
├── app.js               前端主逻辑：导航、题库、题卡、反馈
├── original-reader.js   PDF.js 阅读器封装：页定位、选字、勾画
├── index.html           单页入口
├── style.css            主界面样式
├── original.css         讲义阅读区样式
├── launch.py            启动器：选端口、起服务、开浏览器
├── agent.py             本机模型客户端适配（不保存任何凭据）
├── compile_units.py     章节编译：内容源 + 题库 → unit.json（公开版已移除真实题目）
├── build_unit.py        "编译 + 门禁"一键入口
├── verify_unit.py       章节门禁
├── test_server.py       服务端回归测试
├── smoke_agent.py       模型客户端连通性自检
└── verify_live.py       真实环境联调检查
```

## 六、公开展示版与本地完整版的差异

这是两个不同的东西，不能互相替代：

| 维度 | 本地完整版 V0.1 | 本公开展示版 |
|---|---|---|
| 能否运行 | 能，依赖本地资料布局 | **不能** |
| 讲义 PDF、导图 | 有 | 无 |
| 题库编译产物（167 / 84 题） | 有 | 无 |
| 章节内容源 `content/*.json` | 有 | 无 |
| 内容增强模块 `original_content.py` | 有 | 整份排除 |
| `compile_units.py` 的 PTE 部分 | 含 8 道真实真题 | 替换为 1 道原创占位示例 |
| 课程与题库平台名称 | 原样 | 中性化为"主讲老师 / 题库 / 口诀" |
| 启动脚本中的本机 Python 路径 | 有 | 已移除 |
| 真实会话与追问记录 | 有 | 无 |

**因此：公开展示版的代码经过删减与改写，与本地 V0.1 源码并非逐字节一致；不能据本仓库反推本地实现细节，也不能把本仓库当作完整产品。**

## 八、验收依据（摘要）

- 两个章节均在隔离环境重建，**编译产物**与正式题库逐字节一致（哮喘 167 题，PTE 84 题）。这里比较的是编译输出，不是源码。
- 服务端回归 10 项通过；两章门禁（HTTP、PDF 流、章节路由、入口文件）通过。
- 隔离浏览器验证：进入练习、作答、刷新后恢复、旧题号恢复旧理由、计数更新。
- 已知缺口：提交后分层标签计数需刷新或重新进入练习才重绘；真实学习者体验尚未验证。

完整摘要见 [`docs/验收摘要.md`](docs/验收摘要.md)。
